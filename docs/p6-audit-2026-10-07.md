**Data:** 2026-10-07 · **Tipo:** auditoria somente-leitura (nenhum arquivo do projeto alterado; probes executados fora do repo, em `/tmp`, e removidos após o uso).

Escopo: `crates/second-brain-core` e `crates/second-brain-infra` contra `docs/rust-architecture.md` (FREEZE 2/3) e o plano `docs/superpowers/plans/2026-10-07-p6-vault-sync.md`.

## STATUS

**P6 PARCIALMENTE VALIDADA** — os pilares estruturais estão implementados e testados (148 testes, clippy/fmt limpos, ordem `.md → SQLite`, preservação de frontmatter, watcher funcional no Linux); porém há 4 gaps **confirmados** de contrato (dois deles funcionais) e 2 riscos Windows *prováveis e não testados* na **plataforma primária**.

## ACHADOS

| ID | Classificação | Área | Achado | Evidência | Severidade |
|---|---|---|---|---|---|
| A-01 | CONFIRMADO | Embed guard | `create_note` e `persist_note` **não gravam `file_state`** → no ciclo create/update → próximo `sync`, `get_file_state` = None → `changed = true` → `search.index` **re-embeda** a nota de novo (2 chamadas NVIDIA por edição; amplifica o problema com a cota ~40 RPM) | `application.rs:212-239` e `:315-345` não chamam `put_file_state`; `sync` (`:388-411`) usa `unwrap_or(true)` em estado ausente | **Alta** |
| A-02 | CONFIRMADO | Sync/G3 | Erro de **parse aborta o sync inteiro** (`parse_note(...)?` propaga), contrariando INDEX/F14: "notas com erro de parse entram em `errors[]`, **nunca** abortam o sync". Hoje praticamente nenhuma nota produz erro no parser real (opaco tolerante), então o impacto é latente, mas a cláusula de contrato está violada estruturalmente | `application.rs:390`, `:416` (`?` dentro do loop) | Média (latente) |
| A-03 | CONFIRMADO | Crash/tx | Falha no meio da transação (`search.index`, `commit`) deixa tx **aberta sem rollback**: `in_txn` permanece `true` → toda mutação seguinte falha com "transaction already active" até fechar/reabrir a store. INDEX dizia "falha → transação faz rollback"; não há `Drop` com rollback em `SqliteStore` | `application.rs:337-344`, `:339-343`; `store.rs:366-401` (erro de `commit` mantém `in_txn`); grep não encontra `impl Drop for SqliteStore` | Média |
| A-04 | CONFIRMADO | G1/durabilidade | G1 exige fsync do arquivo **e do diretório**: só o arquivo é `sync_all` antes do rename; **não há fsync do diretório** após `fs::rename` → crash pós-rename pode perder a entrada do diretório no FS → perda do `.md` recém-criado no pior caso | `vault.rs:132-140` (temp fsync + rename, sem dir fsync) vs `rust-architecture.md:200` (G1) | Média |
| A-05 | CONFIRMADO | Fingerprint | fingerprint é `mtime+size` apenas; política CONSISTENCY #5 pedia **mtime + size + sha256** para conflito; INDEX pedia mtime+len. Mudança de conteúdo com *mesmo size e dentro da mesma resolução de mtime* não muda o stat → embedding fica stale (só o embedding; FTS/note são relidos) | `vault.rs:144-162` vs `rust-architecture.md:217` (`mtime + size + sha256`) | Baixa-Média |
| A-06 | CONFIRMADO | Watcher | Eventos `Modify(Name(RenameBoth))` são **silenciosamente descartados** (guard `!matches!(kind, ModifyKind::Name(_))`). Linux/inotify entrega o trio From/To/Both (verificado em probe) → rename funciona no Linux; no Windows/`ReadDirectoryChangesW` `Both` pode ser a única forma entregue → rename **invisível** ao watcher (Deleted+Created nunca chegam até o próximo sync integral) | `vault.rs:303-310`; experimentos com `notify 6.1.1` (Cargo.lock:601) | Média (Windows), Baixa (Linux) |
| A-07 | PROVÁVEL | **Windows** | `fs::File::open(&tmp).and_then(sync_all)`: `FlushFileBuffers` em handle **read-only** falha no Windows (exige `GENERIC_WRITE`). Se confirmado, **toda escrita de nota falha** na plataforma primária — mas o arquivo fica escrito e fechado (o write ocorre; o erro do fsync gera `Err` pro Application → DB não commita; estado consistente, operação opaca como falha) | `vault.rs:134-136`; gate executado apenas em Linux | **Alta** (se confirmado) |
| A-08 | CONFIRMADO | TOCTOU | Stat↔read tem janela: em `sync`, `stat` é tomado depois do read e usamos o stat pré-index; em `sync_file` o stat é lido 2× e gravado depois do index — escritor externo no meio marca `file_state` "fresco" de embedding mais velho que o arquivo atual | `application.rs:388-402`, `:480-510` | Baixa |
| A-09 | CONFIRMADO | Watcher | `WatchHandleImpl` sem `Drop`; sem `stop()`, a thread (e o watch recursivo) ficam vivos para sempre no processo | `vault.rs:252-259` | Baixa |
| A-10 | CONFIRMADO | Conflito | Detecção usa comparação semântica (body após `strip_frontmatter` + FM estrito quando fiel; **não** usa hash). Cobertura: mudanças de body ✓; mudanças só em FM quando o parser reproduz o FM ✓; em FM opaco ✓ nunca gera falso-positivo *mas também não detecta* — porém o editor garante G2 preservando o bloco (saída raw) → **não há sobrescrita externa** | `application.rs:60-151`, `315-335` | Baixa (design) |

## ARQUITETURA

```text
CLI ───────┐
           ↓
       Application   ← nunca importa infra ✓ (grep vazio)
           ↓
         Domain      ← somente std ✓
           ↑
      Ports/Traits
           ↑
         Infra       ← vault/search/store são adapters ✓
```

- **Core → Infra**: nenhuma importação de `second_brain_infra` no core. ✓
- **Application → SQLite direto**: não; só via `StorePort`. ✓
- **Vault adapter**: só fs/notify/path-safety; `REQUIRED_DIRS`/`IGNORED_DIRS` são contratos do vault, não regras de fluxo. ✓
- **Watcher**: transforma notify → `VaultEvent` com debounce; index/embed ficam no `Application` (`apply_vault_event`). ✓
- **Store**: exclusividade da persistência derivada (`file_state` aqui, coerente com "derivado"). ✓
- Ressalva declarada em log: `MarkdownEditor` no core = D-P6-1 (coerente com o freeze — regra de produto). ✓

**Conformidade arquitetural: confirmada.**

## TESTES FALTANTES (priorizados)

1. **Windows** — rodar a suíte completa em Windows antes do P7 ser expoável a usuários.
2. **Crash consistency** — (a) kill/abort entre rename e commit → reindex conserta; (b) falha de COMMIT forçada → confirmar estado e recuperação; (c) temp órfão pós-crash (cleanup no startup ausente — confirmar intencional).
3. **Restart** — abrir/fechar store, `file_state` persiste e embed-guard segue, com componentes reais (Vault + SqliteStore + FtsSearch).
4. **Conflito externo** — (a) mesmo size + conteúdo diferente (sem sha256); (b) mesma resolução de mtime no FS real; (c) FM-only edit com parser real; (d) create+update+sync encadeados sem sync intermediário.
5. **Watcher** — (a) `Rename(Both)` via unit-test direto de `map_events`; (b) overflow de fila sob flood; (c) delete de diretório com `.md` (hoje só probe manual); (d) `stop()` antes/depois do flush.
6. **Embed guard** — (a) ciclo create→sync com infra real (exporia A-01); (b) falha de embed → `embedded=false` persistido → re-tentativa; (c) 1 arquivo modificado entre N inalterados → exatamente 1 embed.
7. **Frontmatter** — completar 16 fixtures × 3 ações (faltam: `:`/vírgula em valor, `aliases` Obsidian, `---` em string, combinações).
8. **Grandes volumes** — sync com 10k arquivos (seen-contains O(n²)); watcher burst; `reindex --force`.

## DECISÃO

**P6 VALIDADA COM RESSALVAS.**

Os fundamentos (vault primeiro, atomicidade, não-corrupção de FM, G3 recuperável, conformidade arquitetural, debounce 250ms, watcher funcional) estão implementados e evidenciados. Porém há 4 gaps contratuais confirmados (A-01, A-02, A-03, A-04) e 2 riscos potencialmente bloqueantes na **plataforma primária** (A-06/A-07) que só executam no Windows.

Escolha "com ressalvas" (não "bloqueada") porque: (a) os gaps têm reparo pequeno e localizado; (b) o gate oficial desta sessão é Linux; (c) o binário ainda não está embalado. Porém **P7 não deve ser exposta a usuários antes do gate Windows (W-1/W-2)**.

## IMPACTO NO P7

**P7 pode começar:**
- Wiring do binário `memory` (sync / watch / search / create / reflect) — os achados não mudam a API pública dos ports.
- Unit-tests de `map_events` com eventos construídos (cobre A-06 sem hardware Windows).
- Execução da suíte no Windows (etapa de gate, não de design).

**P7 deve aguardar (resolver antes ou como coroamento de P6.5):**
1. **Gate Windows obrigatório**: A-07 (W-1) e A-06 (W-2).
2. **Pacote P6.5 de correções mínimas**: A-01 (gravar `file_state` em create/persist), A-02 (parse-error → `errors[]`, não abort), A-03 (rollback automático/Drop na store), A-04 (fsync do diretório + avaliar cleanup de temp órfão no startup).
3. Caracterização do `createNote` no TS (A-11) para confirmar se a ausência de verificação de existência é regressão ou paridade.
